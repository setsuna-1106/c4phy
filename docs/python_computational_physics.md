# Python 计算物理项目规范

> 适用范围：`project/python/` 中新建或实质修改的数值实验、C/C++ 数据后处理与可视化。学习笔记里的短演示可简化，但涉及数值结论时仍须说明模型、单位和验证方法。

本规范的目标是：**别人能复现计算，自己能判断结果是否可信**。文中的「至少」「必须」是交付底线，「建议」「推荐」可按项目规模取舍；简单项目不必为了形式增加目录和依赖。

## 1. 先写清楚物理问题

每个数值实验在同目录的 `document.md` 中至少记录：

1. 研究量、方程、初始条件与边界条件；若使用无量纲量，给出尺度和换算关系。
2. 参数名、单位、取值及来源；说明采用的数值方法和它适用的条件。
3. 时间范围、步长或网格、停止条件、随机种子（如有）。
4. 如何运行，以及至少一种检验结果的方法：解析解、守恒量、极限情形、步长收敛或独立实现对照。

修改物理模型或算法时同步更新这些内容。暂时未知的物理量或误差界直接标为「未验证」，不要把数值曲线当作证明。

## 2. 目录与代码组织

遵循 [项目命名规则](naming_conventions.md)：`project/python/<snake_case 项目名>/`，入口为 `main.py`，项目内有 `Makefile`，并在根 `Makefile` 注册。历史项目 `random_walk.py` 保留原名。

单文件练习可以只用 `main.py`；当计算、输入输出和绘图已经难以分别阅读时，再拆成 `model.py`、`solver.py`、`plot.py`。`main.py` 负责参数与流程，计算函数不应在导入模块时自动运行。推荐结构：

```text
project/python/example/
├── main.py           # 参数、调用、命令行入口
├── solver.py         # 可选：模型与数值计算
├── plot.py           # 可选：画图
├── document.md       # 物理模型、方法、验证与运行方式
└── Makefile          # all / run / clean
```

- 函数名、变量名用 `snake_case`；物理符号可在公式中用 `x, v, m`，代码中优先用可读名称，如 `angular_velocity`、`time_step`。
- 对外使用的计算函数写简短 docstring，说明参数和返回值的**单位、形状、坐标轴含义**。数组形状如 `(n_steps + 1, 2)` 应明确第二维代表什么。
- 参数传入函数，避免可变全局状态和魔法数字。`main()` 放在 `if __name__ == "__main__":` 下。
- 遵循 PEP 8 的基本格式：4 空格缩进、导入按标准库/第三方/本项目分组；可复用函数建议标注参数和返回值类型。计算函数返回数据，不负责 `print()`、存盘或弹出图窗；输入无效时给出明确错误，不用裸 `except` 吞掉问题。
- 优先使用标准库、NumPy、Matplotlib；确实需要求根、积分、优化等成熟方法时再引入 SciPy，并记录依赖。不要为了套模板引入类、配置框架或复杂命令行接口。

## 3. 数值计算的底线

- **精度与边界**：默认使用 `float64`。确定网格端点是否包含在内；检查数组长度、有限值、参数范围和不合法初值。不要用 `==` 比较浮点近似结果。
- **方法与误差**：写明算法阶数和适用条件。至少做一次改变步长或网格后的比较；非零参照量可报告相对误差，接近零时改用绝对误差，并说明容差。看到收敛前不要只凭一张图下结论。
- **物理检查**：按模型选用量纲、符号、对称性、边界行为、概率归一化、能量或动量等检查。守恒量只有在模型确实守恒时才用于判错；耗散或受驱动系统要使用对应的能量收支。
- **随机过程**：用 `np.random.default_rng(seed)` 创建局部生成器并显式传入计算函数；记录种子、样本数、估计量及不确定度。单条随机轨迹不能代替统计结果。
- **性能**：先写正确的基线实现并测量瓶颈，再考虑 NumPy 向量化、Numba 或 C/C++。保留能与优化版比对的小规模算例；不以速度牺牲验证。

`numpy.isclose`/`allclose` 的容差应按物理尺度设定，不能直接把默认值当作任何模型的误差标准。

## 4. 数据、复现与画图

- 从脚本自身位置定位输入文件，如 `Path(__file__).resolve().parents[2] / "c" / "example" / "result.csv"`；不硬编码本机绝对路径。缺少前置 C/C++ 输出时，报出缺失文件和生成命令。
- C/C++ 与 Python 交换 CSV 时，明确列顺序、列名、单位、分隔符、是否有表头，以及一行表示一个什么观测；读取时按约定设置 `skiprows`，检查列数与数据范围。用 `np.loadtxt(..., ndmin=2)` 读取可能只有一行的表格，避免形状意外变化。可重新生成的 CSV、图像输出和缓存属于生成产物，不作为手工维护的源文件。
- 对可复现实验，记录运行命令、Python/关键库版本、参数、种子、输入数据来源与算法版本。实验结果依赖的外部原始数据要说明取得方式；不可再生成的数据不要因为通用 `.gitignore` 而丢失。
- 图必须标注横纵轴物理量及单位，图例要能区分曲线；需要比较时，画出解析/参考结果、误差或守恒量。交互探索可用 `plt.show()`；需要汇报时保存到项目的输出目录，并在文档中写出生成命令。

## 5. 最小验证标准

`make` 当前只做 Python 语法检查，**不代表数值正确**。完成一个数值实验前，至少执行：

1. 一次小规模运行，确认输入、输出、形状和数值范围正确。
2. 一个与物理问题相关的基准检查，例如简谐振动的解析解、自由粒子匀速、扩散方程的质量守恒或随机游走的均方位移趋势。
3. 一次步长/网格/样本数敏感性检查，并记录比较量和容差。
4. 检查生成图的坐标、单位、图例和趋势；运行 `make` 与 `git diff --check`。

当算法可复用或已有错误风险时，把上述基准写成 `test_*.py`；容差依据物理尺度和预期算法误差设定。纯绘图脚本至少检查读取契约、空/缺失数据和坐标标签，不必为每张图引入完整测试框架。

## 6. 新项目交付清单

- [ ] `document.md` 能让别人说清模型、单位、算法、参数与运行方式。
- [ ] 代码将计算与展示分开；计算函数可用小输入独立调用。
- [ ] 记录随机种子或明确说明非确定性来源。
- [ ] 有物理基准和收敛/敏感性证据，图的坐标及单位完整。
- [ ] 项目 `Makefile` 可运行，根 `Makefile` 已注册，生成文件不混入源代码提交。

这是**新项目的目标规范**；旧可视化脚本可在修改时逐步补齐，无需为遵守文档而一次性重构。
